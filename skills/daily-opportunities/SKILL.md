# Daily opportunities

Run the loop defined in the
[research-partner workflow](../_shared/research-partner-workflow.md):

**Goal → Segment rules → List → Review → Learning → Refinement**

The segment's Required, Prefer, and Exclude rules are the hypothesis. Do not
create a separate hypothesis page.

## Choose the next action

Confirm the company, noticed team, goal, and segment. Read its current rules,
historic Lists rows, noticed list, review evidence, and learning log.

- No list: prepare the first batch.
- Preparing: resume the same batch.
- Awaiting reviews: preserve the batch and report the remaining count.
- Reviewed: record learning before changing rules or starting another batch.
- Conflicting evidence: reconcile it rather than inferring a result.

A new day does not require a new list. An explicit Yes can move to Outreach while
the rest of the batch remains under review.

## Prepare the batch

Find 25 defensible people unless the user requests another batch size. Evaluate
only public or enrichment-supported facts. Required rules must match; Prefer
improves rank; Exclude disqualifies. Missing data is unknown.

Rank by rule fit, relevance now, and credible relationship path. Deduplicate
within the batch and against people already approved, contacted, or dropped for
the same goal. Connectors are ordinary segments defined by observable access or
community signals; never assume willingness to introduce.

Each opportunity needs enough public evidence for a quick decision: person and
role, company, relevant company facts, matched signals, relationship path, concise
fit reason, and sources. If 25 credible matches are unavailable, keep the list
Preparing and report the shortfall rather than weakening the rules.

## Publish and verify

Create or resume one noticed list and one Lists row for the batch. Follow the live
tool contracts and template instead of assuming stale field or argument names.
Keep membership stable once review starts.

Configure the review statement from the workflow contract. Read back the full
list and review setup, including all pages. Verify the intended people, reviewer,
question, access, and review URL. List membership is not human approval. Only then
mark the row To review and save the review URL.

When a Yes moves to Outreach, connect it to this exact Lists row through Source
list.

## Learn and refine

Use explicit Yes, No, and Not sure verdicts. Not sure is reviewed but not Yes;
silence or disappearance is unreviewed. Preserve valid verdicts without requiring
a reason.

After enough feedback, update Results, add one learning row, and make the smallest
supported rule change. Preserve the historic list, membership, verdicts, and
previous rules. Avoid conclusions from a single example or a small rate change.

Update opportunity metrics for the correct goal and report the review count,
learning, refinement, and next responsible person.
